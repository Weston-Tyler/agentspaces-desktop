# AgentSpaces Desktop alpha

The companion helps find and reuse work in native tools, including forgotten work in the same tool. Desktop, CLI and supported IDE surfaces remain first-class. Current, dormant and archived sessions are logical participants; they need not run a model or be separate network peers.

Discover metadata by project, topic, artifact and recency. Separately grant bounded content access, retrieval/sharing, and execution. Discovery never grants content access or wakes sessions. Preserve the native source/session/version, filesystem/worktree and account/project boundary. GUI and CLI can refer to the same session, not independent execution controllers.

AgentSpaces is the participant/work/lease/result authority. Application permission settings, derived metadata caches, audit and usage records do not replace it. Retrieved material is untrusted data. Large assets use upstream content identifiers and asset references; this first alpha offers bounded text artifact inspection while remote asset/block exchange remains gated.

## Current interaction model, 2026-10-09

The source implementation supports automatic source-bound registration, capabilities, peer discovery, room creation/join/invite/read/post, one-peer native messaging, multiple-recipient/date/topic messaging, empty persistent Codex work-chat creation, finding retrieval, workspace artifact search/read and indexed worktree comparison. New rooms permit eligible connected threads to join. Existing room and workspace rules govern first-access admission without repeated per-thread owner additions. Source selection preserves current account/scope boundaries and refusals.

`message_agents` resolves explicit source/native IDs, room-wide `@all`, `@recent(30d)` and `@topic("chillit recipe")` against the existing metadata catalog. Topic/date filters intersect; unknown native activity is explicitly omitted for a date filter. Matching cached metadata precedes the bounded current-source grant checks so later catalog pages can still supply relevant peers. Recipient identities and delivery receipts persist before bounded group posting; a retry cannot acquire a wider audience. Human posts keep owner attribution. Native eligibility and current grants are checked again by delivery.

Source tools and authenticated owner surfaces cover the application's implemented interactions without creating another runtime or registry. Owner account/permission/policy/service settings, native consent and model budgets remain their respective owner's interfaces. Standing grants persist; adding another eligible connected thread or retrying a permitted registration does not require new approval. Every capability response must distinguish configured native tools, loaded tools, room admission and connected inbound delivery.

Windows/Linux alpha packaging provides normal launchers; Windows also registers Installed apps and an uninstaller. Owner browser sessions survive normal companion restarts for up to 30 days. Ask restores at most 100 recent questions/answers for 30 days, with source references and coverage; clearing that view retains effect receipts. Connected metadata and discussions persist in the owner-private workspace. Neither saved context nor conversation receipts establish full interrupted-lane recovery. See [addressing and collaboration](agent-addressing.md), [background operation](headless.md) and [installation](installer.md).

The dated development slices below record prior authority and qualification. Current native wake remains adapter-dependent: remote Codex's owning daemon and an opted-in available Claude channel are supported routing paths; no universal cloud/web discovery or arbitrary-host execution claim follows. Shared work board, resource broker, phone decision inbox and complete lane recovery remain outstanding.

## Authorized development scope, 2026-10-08

This repository owns the standalone desktop application, native adapters, tests, scripts and product documentation. Deployment permissions are supplied by each installation owner; historical development notes grant no access to a user’s machines.

The supported topology includes native Codex and Claude sessions on a configured Linux SSH host and a local Windows workstation. Host-aware discovery, original native IDs, CLI workflows and account/project boundaries are therefore first-class. Each host/provider/folder gets an explicit discovery target within an intentionally linked logical project. No blanket native-history enrollment or inferred execution permission follows from metadata discovery.

Private-history enrollment, account connection, native session execution and paid inference still need their specific explicit grants/budgets. Publication, push/merge, release, license/visibility change, transfer, recurring automation and shared deployment changes remain outside this lane. Tool-enforced sandbox prompts are distinct from the owner's grant.

## Authorized bounded E2E slice, 2026-10-08

The owner explicitly requested subagent implementation and working end-to-end behavior, then selected a live-test cap of up to five short native questions with 90-second timeouts and requested 800-token answers. Three disjoint subagents covered native adapters, Ask retrieval/effect safety and targeted owning-runtime protocol proofs. Native answering, full-catalog topic matching, selected-source citations, owner-authenticated Ask HTTP/UI, cancellation and usage/coverage are implemented. All five questions completed: two browser-driven fresh answers and three queue turns on two owned read-only Codex threads, including continuity on the same original native UUID. The topic sources were explicitly synthetic; the answering model was real. Original queue tokens were not durably retained and remain unknown. A final harness assertion over CBOR object prototypes failed after the native turns completed; evidence was recovered with zero additional inference and republished through fresh signed targeted Java work. No original signed snapshot claim follows from that recovery.

Claude API answering is implemented and fixture-tested but API environment credentials are absent. Arbitrary existing-thread fan-out remains unwired/gated: native metadata reads do not expose a verifiable current permission profile, and cold threads cannot be silently resumed. No consumer OAuth credential relay, private-history injection, API-account connection, push/merge, release or other-product deployment occurred. See native-questions.md for the implemented contracts and exact proof boundaries.

## Connected-agent requirements, 2026-10-09

The owner requested agents that register themselves, find relevant connected peers, start group discussions, join open discussions and exchange context without manual membership requests for each thread. Existing account/workspace grants and explicit source refusals remain authoritative. New app-created and agent-created groups permit eligible peers to join; existing rooms retain their owner-controlled self-registration setting. The owner subsequently authorized tested changes to be pushed to the existing GitHub repository and requested immediate deployment to the existing computers. Those task grants extend the earlier local-only boundary.

The owner then explicitly approved a public repository and Apache 2.0, with prominent attribution to [AgentSpaces by BadMonkey](https://www.badmonkey.ai/agentspaces/) and links to the company/framework ecosystem. The standalone desktop repository remains the application's owner; a company-owned repository transfer is a separate decision. Record actual publication, versioned artifacts and installed runtime verification after completion rather than inferring them from this approval. See [brand and attribution](brand-and-attribution.md) and [release readiness](open-source-readiness.md).

Implemented in this slice: native source registration, metadata-only discovery of joinable rooms, idempotent bound-source joining, current-member invitations, creator-bound peer groups, one-peer and filtered/multiple-recipient messaging with durable receipts, MCP/CLI/API surfaces and the owner-visible room setting. New remote source lookup uses the existing native daemon through a bounded metadata-only adapter. Registration remains separate from inbound native delivery and work authority. `create_native_thread` is the connector's supported empty Codex work-chat interface; it does not impersonate or install the native application's `create_thread` tool.

The following operational requirements extend this existing brief. Reported interruptions and queue waits are owner-supplied incident evidence, not independent runtime qualification. They are requirements for subsequent bounded implementation, not claims that this slice completes them.

The owner additionally requested that every implemented interaction surface expose a supported agent interface and that collaboration defaults ship with new setups. The current scoped MCP/CLI/API includes native empty-thread creation, room invitations, first-access admission to open rooms, capabilities and worktree comparison. Global source permissions, account sign-in, native consent and service administration remain owner-controlled surfaces; agents can inspect these boundaries through capabilities. Native thread creation inherits provider defaults and starts no model. Cloud/consumer-web adapters and a shared work/resource/decision runtime remain separate implementation work.

Portable collaboration defaults now ship in the installed router: one lane/file-set owner and isolated worktree; written briefs; one owning program record with same-day intake; freshly verified remote bases; the existing per-host test gate (default 15-minute lease, demo/release priority with starvation prevention); meaningful evidence before acceptance; explicit publication grants that retain standing/task authorization; bounded usage and expiring claims; safe reconciliation after restart; and an inference-free setup self-test. These rules inform upstream contract extensions. The router is guidance, not enforcement or a replacement board/broker.
