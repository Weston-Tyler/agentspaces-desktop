# Connected work map

The Connected Work page discovers permitted sessions, local codebases, linked worktrees, Markdown and work/artifacts without requiring a user to remember thread IDs or native storage locations. Select this Windows device and/or remote, choose native tools, and connect one scope. Locations default to supported native working-directory metadata plus conventional workspace folders; explicit roots are an optional override.

The map is a derived read-only index. It does not own tasks, authority, leases, scheduling, integration or release acceptance. AgentSpaces remains coordination authority; Git, native tools, files and each product's controls retain their ownership.

## Permissions

- Metadata policy discovers catalogs without opening transcripts or waking models.
- Broad local retrieval derives enrollment/content/share/retrieve grants for known-location sessions in this selected scope, so individual enrollment is optional. Per-session overrides and scope revocation still refuse access.
- Code/document indexing is its own read grant for local/SSH filesystem evidence. Sensitive caches, credentials, private-key extensions, hidden directories and patent foundations are excluded. This is a conservative exclusion policy, not a complete secret detector.
- Folder exclusions use the host's path rules. An account label is a local permission domain, not authenticated proof of historical provider account ownership.
- No native execution, external fabric publication, merge, deletion, archive, release or recurring scan is implied.

Policies activate with the completed inventory batch. Revoke stops permission immediately and cancels any active batch. Cancellation keeps the previous index; it does not roll back or alter source repositories.

## Discovery and coverage

Codex uses native thread/list with all documented source kinds and separate current/archive paging. Claude uses the pinned SDK listSessions without a directory restriction for broad discovery, including programmatic sessions. Claude does not expose a qualified current/archive state; it remains unknown. Native rows without a working directory remain visible when their exclusion boundary can be established, but receive no automatic content grant and no invented location.

Native pages are capped per batch and retained across continuation. Filesystem batches have directory/file/time/node/response budgets and preserve a read cursor. Continue remaining inventory advances the saved folder queue rather than repeatedly visiting the same first files. Coverage, errors, exclusions, skipped symlinks and limits stay visible. This is not a promise of an instantaneous whole-machine census.

Source caches persist under the app's owner-only state directory. Restart restores metadata with a stale label. Rebuilding a corrupt derived cache does not invent native histories or grants. Individual observations keep their source versions, hashes and observation times; a multi-batch index is not one atomic snapshot of concurrent work.

## Repository and worktree evidence

The reader uses Git common-directory identity to group linked worktrees. Separate clones with matching sanitized origin URLs are only a possible family, not the same repository. Bare stores are repositories with no fictional working trees.

Worktree comparison requires the same observed repository and exact captured heads. It reports common base, left/right-only commits, committed file deltas, local dirty patches, untracked hashes and overlapping local paths. A changed head or redirected path requires refresh. Git hooks, filesystem monitors, external diff helpers and text converters are not run by comparisons. No comparison determines a safe merge, verification, publication or deletion.

Git status and indexed blob references distinguish tracked, modified, untracked and possibly ignored material. A tracked file is not thereby integrated or accepted; scratch location does not make a file disposable.

## Document and artifact relationships

- Explicit Markdown links are confirmed references to already indexed targets.
- SHA-256 equality means identical observed bytes.
- UTF-8 text normalized only for CRLF/LF can establish same text with different bytes; those files retain distinct byte hashes.
- Similar titles and matching clone origins are suggestions, not semantic equivalence or authority.
- UUID mentions can link documents to discovered native session IDs, but do not prove authorship. Ambiguous host/provider matches remain suggested.
- Native working directory establishes session/worktree context, not who created a file.

Exact-file inspection checks current bytes against the indexed digest, refuses stale or redirected files, and returns a bounded untrusted-text excerpt with host/path/hash references. Binary and large-asset transfer remain on the upstream asset/content-addressed mechanism gate.

The index does not promote a claim in a Markdown file to verified work. Tests, acceptance, integration, publication and retirement remain unknown unless separately established by their owning evidence/control path.

## Native entry points

The existing scoped MCP connector now provides four read tools: discover_permitted_work, retrieve_permitted_finding, search_workspace_context and read_workspace_artifact. Workspace search/file reads require the connector's active broad scope. Legacy project-only tokens cannot access the broad index. Retrieval is deterministic and invokes no model; the user's native tools retain normal permissions and approvals.

A connector is still bound to an explicitly selected logical participant; universal per-native-thread caller propagation remains unqualified. Scope discovery does not make every thread a network peer or execution controller.

## Validation boundary

The fixture uses actual temporary Git repositories/worktrees with explicitly synthetic sessions/docs, divergent commits, dirty and untracked files. It disables fixture hooks/signing and tests comparisons, links, hashes, exclusions, budgets, cancellation, continuation, restart and revocation.

Live metadata reads have been exercised on both hosts with no transcript read or model call. Automatic filesystem inventory has observed hundreds of repositories and over a thousand worktrees within bounded partial scans. Exact counts and limits belong in the per-run task evidence. No other-product source, native rollout file, shared service or cloud deployment was changed.

The existing source-alpha release/privacy, native execution, AgentCard publication, sealed-space and private-content fabric admission gates remain unchanged.
