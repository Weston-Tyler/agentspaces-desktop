# AgentSpaces 0.5 integration

Desktop consumes the Bad Monkey [TypeScript 0.5.0 binding including the TLS update](https://github.com/badmonkeyai/agentspaces-typescript/tree/b28f01194da107ba9544392c1e280dcd3bc1fda1) on wire v3. The newer [Java 0.5.1 and ModelCard source](https://github.com/badmonkeyai/AgentSpaces/tree/bd7096ff132eed0ffb813edba8d3e2cf99b0ed23) and [model-wire gateway definitions](https://github.com/badmonkeyai/agentspaces-model-wire/tree/5cfcc734c55f1604ea5339898f39b483702c516c) are upstream references, not bundled Java services. The desktop continues to use the same upstream signed records, claims, leases and work replica.

To observe an existing private fleet, open Setup → AgentSpaces fabric. Enable workspace observations, select TLS, and supply the local forwarded seed port, the expected seed PeerID from a trusted source and the self-certifying group ID. This connection accepts only a literal loopback endpoint. It checks the TLS 1.3 channel identity against the configured seed before sending AgentSpaces frames, then independently verifies the group founding. It does not fall back to plaintext if TLS fails. The fixture-only TCP connection remains available for interoperability tests.

With workspace observations selected, the active workspace and exact account, source and retrieval grants control reads. Usage shows verified AgentCards and ModelCards; a ModelCard is a signed publisher assertion of advertised capabilities, not a health check, model entitlement or execution route. Usage counters, advisory votes and local semantic matching remain separate optional views. No native thread, artifact, or chat history is advertised by these views. The peer connection does announce its own fabric identity as part of the upstream protocol.

DTLS and QUIC between managed Java gateways, and QUIC for Desktop's native transport, remain separate from this loopback TLS path. This update does not start or upgrade a gateway, enable a seed, enroll private histories in the fabric, invoke a model advertised in a card, or make content swarm transfers, ordered execution or sealed-space decryption available in Desktop. Those need explicitly configured upstream services and separate qualification.
